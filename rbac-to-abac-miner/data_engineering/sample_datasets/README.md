# sample_datasets/ — Planted Pattern Documentation

Owner: **Shweta**. Generated by `generate_sample.py`. Both datasets use seed 42 by default.

> **⚠ Ground-truth for QA only.** The patterns described below are used by tests and
> the oracle to verify correctness. They must NEVER be passed as a feature or label to
> the ML pipeline — the pipeline must discover them independently.

## Reproduce the datasets

```bash
# from the repo root
python data_engineering/sample_datasets/generate_sample.py --size small  --seed 42 --out data_engineering/sample_datasets/small
python data_engineering/sample_datasets/generate_sample.py --size medium --seed 42 --out data_engineering/sample_datasets/medium
```

Same seed → byte-identical files every time.

## Planted pattern (ground truth)

### Role assignment (UA — user_roles)

Each user is assigned a **primary role** determined by their `department`:

| Department | Primary Role |
|------------|-------------|
| Finance | R01 (Finance_Analyst) |
| HR | R02 (HR_Specialist) |
| Engineering | R03 (Engineering_Lead) |
| Legal | R04 (Legal_Advisor) |
| Operations | R05 (Operations_Manager) |
| Marketing | R06 (Marketing_Executive) |
| Security | R07 (Security_Officer) |
| IT | R08 (IT_Admin) |

~10 % of users are given an additional **random noise role** (different from their primary role). This means a decision tree trained on this data should find: `IF user.department == "Finance" THEN role is likely R01`, with ~10 % exceptions.

### Permission assignment (PA — role_permissions)

| Rule | Scope | Explanation |
|------|-------|-------------|
| Every role gets `read` | All resources (`resource_id = ""`) | Universal read — tests D-001 blank resource_id path |
| Every role gets `write` | Only resources where `resource.department == role's department` | Scoped permission — tests D-001 non-blank resource_id path |
| ~25 % of roles get `delete` / `admin` / `execute` | All resources | Random extra permissions for variety |

### Expected learnable pattern for the Decision Tree

```
IF user.department == X AND resource.department == X  → write is authorised
IF (any user)                                         → read is authorised
```

The classifier should achieve high F1 on this data because the pattern is clean with ~10 % noise.

## JSON format

`dataset.json` in each size folder contains all six tables as a single object:

```json
{
  "users":            [...],
  "roles":            [...],
  "permissions":      [...],
  "resources":        [...],
  "user_roles":       [...],
  "role_permissions": [...]
}
```

This matches the JSON format specified in `docs/modules/DATA_CONTRACTS.md` §"Dataset file formats".

## Implementation decision: D-001

Permission model: `permission_id` is an **action string** (e.g. `read`, `write`).
`role_permissions.csv` carries an optional `resource_id` column:
- blank / empty string → the permission applies to **all** resources
- non-blank → the permission is scoped to that specific `resource_id`

This is the proposed default from `DECISIONS.md` D-001 and matches the contract examples
in `DATA_CONTRACTS.md`. Jayed, Granthali and Shweta must confirm this against the report PDF.
